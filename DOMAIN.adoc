# Custom domain setup — antora-supplemental.org (Cloudflare)

Registrar / DNS host: **Cloudflare**. You apply these; GitHub/Netlify only consume them.

## Recommended DNS (no `www`)

| Host | Type | Target | Proxy |
|------|------|--------|--------|
| `@` | CNAME | `antora-supplemental.github.io` | See HTTPS note below |
| `www` | CNAME | `antora-supplemental.github.io` | Same as `@` (silences GitHub/Cloudflare apex+www checks) |
| `docs` | CNAME | `antora-supplemental.github.io` | See HTTPS note below |
| `registry` | CNAME | *(Netlify hostname from Domain management)* | Proxied OK (Netlify) |

Cloudflare **CNAME flattening** makes `@` → `….github.io` valid (plain DNS often forbids apex CNAMEs).

**`www`:** Optional for humans (apex alone is enough), but GitHub Pages (and some Cloudflare setup tips) expect apex+`www` together. Add `www` CNAME → `antora-supplemental.github.io` to silence “improperly configured” warnings; it serves the same welcome site as `@`. Redirect `www` → apex in Cloudflare if you want one canonical hostname.

Both `@` and `docs` CNAME to the **same** `antora-supplemental.github.io` hostname on purpose. GitHub routes by the published `CNAME` file + Pages custom-domain binding:

| Hostname | Repo | `CNAME` file contents |
|----------|------|------------------------|
| `antora-supplemental.org` | `antora-supplemental.github.io` | `antora-supplemental.org` |
| `docs.antora-supplemental.org` | `docs` | `docs.antora-supplemental.org` |

## HTTPS / “not eligible for HTTPS” on GitHub

Two different TLS layers:

1. **Cloudflare edge HTTPS** (orange cloud / Proxied) — visitors already get HTTPS via Cloudflare. Site can look “live on https://…” while GitHub still complains.
2. **GitHub Pages Let’s Encrypt cert** — required for GitHub’s “Enforce HTTPS” checkbox. GitHub must see DNS pointing at **GitHub**, not Cloudflare proxy IPs.

If GitHub says the domain is **not eligible for HTTPS**:

1. In Cloudflare DNS, set `@` and `docs` to **DNS only** (grey cloud), not Proxied.
2. Wait a few minutes; in the repo **Settings → Pages**, remove and re-add the custom domain (or wait for the cert job).
3. When the checkmark appears, enable **Enforce HTTPS**.
4. Leave grey-cloud permanently for GitHub Pages hosts (simplest), **or** orange-cloud again knowing GitHub’s cert may not renew until you grey-cloud again.

CAA records (if any) must allow `letsencrypt.org`.

Netlify `registry` can stay Proxied; that is unrelated to GitHub’s cert issuance.

## Registry OAuth / Better Auth (Netlify env)

```
BETTER_AUTH_URL=https://registry.antora-supplemental.org
BETTER_AUTH_TRUSTED_ORIGINS=https://registry.antora-supplemental.org
```

Callbacks: `https://registry.antora-supplemental.org/api/auth/callback/<provider>`
